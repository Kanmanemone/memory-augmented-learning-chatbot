# PRD: lossy_clone

## 목표
`memory-augmented-learning-chatbot`(원본)의 "3계층 메모리(STM/LTM/Episodic) 학습 챗봇"이라는 개념만 참고해서, 코드를 베끼지 않고 처음부터 다시 짠 독립 실행형 챗봇을 단계적으로 만든다. 원본 코드는 수정하지 않고 오직 읽기 참조만 한다.

## 사용자
원본 프로젝트의 구조(메모리 계층 개념, `chat()` 루프)를 손으로 다시 짜보면서 이해하려는 1인 개발자(본인). 배포 대상이 아니라 학습/실습용 산출물이다.

## 원칙: "복제처럼 보이지 않는 복제"
- 원본 코드를 복사-붙여넣기하지 않는다. 함수/변수 이름, 파일 분할 방식, 시그니처를 원본과 동일하게 맞추지 않는다.
- 원본에서 가져오는 것은 오직 **개념과 동작 순서**뿐이다: 세션 내 최근 대화를 저장했다가 다시 읽어 LLM 컨텍스트에 넣는다는 흐름, 나중에 세션 요약을 장기 기억으로 넘긴다는 흐름, 주제별로 학습 이력을 누적한다는 흐름.
- 디테일(정확한 임베딩 차원, 프롬프트 문구, repeat-detection 임계값 같은 것)은 의도적으로 뭉갠다. 단계마다 필요한 만큼만 채운다.
- `lossy_clone/` 폴더는 완전히 독립적으로 동작해야 한다. 이 폴더만 잘라내서 다른 위치에 붙여넣고 실행해도 그대로 동작해야 하며, 원본 프로젝트의 다른 파일(`chatbot.py`, `memory/`, `episodic_schema.py` 등)을 import하거나 참조하지 않는다.
- LLM 연동은 실제로 호출되어 동작해야 한다. 장식적인 optional/fallback이 아니라 진짜로 대화가 되는 것이 목표이며, 다만 특정 벤더에 고정하지 않고 교체 가능하게 분리한다.

## 핵심 기능 (단계별 로드맵)
구현은 처음부터 한 번에 만들지 않고, 아래 순서로 조금씩 쌓는다. 각 단계가 끝나면 그 자체로 동작하는 상태여야 한다.

1. **1단계 (현재 범위): Chatbot 인스턴스 + STM**
   - `Chatbot` 클래스 인스턴스 생성
   - `chat("...")` 호출 → 응답 반환
   - 대화 중 주고받은 메시지를 세션 내 단기 기억(STM)에 저장하고, 다음 턴에 다시 읽어 컨텍스트로 사용
2. **2단계: LTM (장기 기억)**
   - 세션 종료 시점에 STM을 요약해 장기 기억으로 전이
3. **3단계: Episodic memory (일화 기억)**
   - 주제별로 학습 이력(강점/약점/질문)을 누적
4. **4단계: 검색/통합 및 디테일**
   - LTM/Episodic 검색, 반복 질문 감지, 통합 컨텍스트 구성 등 원본에 있던 세부 동작 중 필요한 것만 선택적으로 따라간다

## MVP 제외 사항 (1단계 기준)
- LTM, Episodic memory (2, 3단계에서 다룸)
- Chroma 등 벡터 DB, 임베딩 검색
- 특정 LLM 벤더(Gemini 등)에 대한 하드코딩된 의존 (연동 지점은 교체 가능하게 분리)
- 세션 종료 조건, 반복 질문 감지, topic tagging 등 원본의 정교한 부가 로직

## 디자인
- CLI 또는 최소한의 파이썬 스크립트로 동작 확인 가능한 수준이면 충분하다. UI는 만들지 않는다.
- 원본과 마찬가지로 로컬 파일(SQLite 등) 기반으로 동작하며, 저장소는 `lossy_clone/data/` 아래에 둔다.
